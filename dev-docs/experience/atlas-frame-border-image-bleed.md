# 图集子图用 border-image 九宫格导致整图集串图（彩色条纹）

## 问题现象

真实工程 BaseCard.exml 渲染验收时，牌面左边缘出现橙色/绿色杂色竖条纹（视觉 AI 分析发现），
图像内容本身正确（牌面、数字 7、黑桃都渲染正常）。

## 排查过程

1. 检查该节点（img_mask，scale9Grid="33,13,1,2"，图集子图 puke_card_mask_png）的 computed style：
   `border-image-slice: 958 486 3 472 fill`。
2. 对照图集帧坐标（x=472, y=958, w=175, h=63）：slice 值确实是"帧起点 + 图集余量"。

## 根因

CSS border-image 的 slice 是对**整张源图**切九分。为了让"图集中间那块帧"成为绘制区域，
把 slice 左/上设为帧起点（472/958）、右/下设为图集余量后：

- **四角区域 = 472x958 的巨大矩形**（帧左上角在图集中的整个左上区域），
  里面装的是图集里其他无关精灵；
- border-image 把整个四角区域**缩放绘制到 33x13 的角盒里**——邻居精灵被压扁成彩色条纹。

结论：border-image 只适合"源图恰好就是精灵本身"（直接图片文件）的九宫格，**无法对图集做子矩形九宫格**。

## 解决方案

图集子图九宫格改用 **9 片绝对定位背景**（`nineSliceFramePieces`）：

- 按 EUI scale9Grid 语义（grid 矩形 = 可拉伸中心区，四角固定尺寸）把帧切九分；
- 每片对源子矩形独立计算 `background-size`（整图集按该轴缩放比放大）与
  `background-position`（源点乘缩放比取负）；
- 盒尺寸不足时中段 clamp 到 0；
- 直接图片文件的九宫格仍用 border-image（含 fill 关键字）。

修复后浏览器复测：条纹消失，牌面干净，角部圆角正确。

## 预防/注意事项

1. border-image 的 slice 坐标永远是"源图整体坐标"，与精灵在图集中的位置无关。
2. 视觉链路必须浏览器实测收尾（本项目 CLAUDE.md 硬性规则 2）——本例字符串断言全绿，
   实际渲染串图，靠截图 + 图像分析才发现。
3. 九宫格中心区判读：EUI/Flash 的 scale9Grid 矩形是"会拉伸的中心区"，四角是矩形外的固定区域；
   不要把 grid 当成"四角大小"直接切片。
