## 一、项目目标

### 1.1 核心目标

基于 `fairygui-html-renderer` 已有的工程结构和基础设施，建立独立的 Egret EUI EXML 渲染项目。

第一阶段只验证：

```
Egret 游戏工程
      │
      ├── EXML 文件
      ├── 图片资源
      └── 资源配置
            │
            ▼
       EXML Parser
            │
            ▼
       EXML AST
            │
            ▼
       Scene Builder
            │
            ▼
       Scene Tree
            │
            ├──────────────┐
            ▼              ▼
       Scene JSON      HTML Renderer
                           │
                           ▼
                      HTML / CSS
                           │
                           ▼
                      浏览器预览
```

核心目标是验证：

1. 能否正确解析 Egret EUI 的 EXML 文件。
2. 能否还原基本 UI 节点层级。
3. 能否正确解析节点位置、尺寸和基础视觉属性。
4. 能否正确加载 EXML 引用的图片资源。
5. 能否将 EXML 渲染成浏览器可以展示的 HTML。
6. 能否保留节点原始信息，支持后续 AI 搜索和定位。

### 1.2 本阶段明确不做

为了控制开发成本，第一阶段不实现：

- FairyGUI 与 Egret 的统一抽象层。
- 完整 EUI 运行时模拟。
- EXML 自定义组件完整继承机制。
- State 状态切换。
- Data Binding。
- 动画和 Tween。
- 完整布局引擎。
- 复杂主题系统。
- EXML → FairyGUI XML。
- HTML/React → EXML。
- 多引擎公共 SDK。

对于暂不支持的 EXML 特性，必须记录 unsupported，不允许静默忽略后伪装成完整支持。

## 二、迁移原则

### 2.1 保留成熟的工程架构

不重新发明基础设施，优先沿用 FairyGUI 项目已经验证过的实现。


| 原有模块             | 处理方式     | 说明                             |
| ---------------- | -------- | ------------------------------ |
| Parser           | 重写       | 替换成 EXML Parser                |
| Scene Builder    | 重写       | 替换为 Egret Scene Builder        |
| Scene JSON       | 参考后重写    | 保留对 AI 输出结构化节点数据的能力            |
| Renderer         | 部分复用     | 保留渲染器组织方式，替换 FairyGUI 节点实现     |
| Renderer Nodes   | 重写       | 建立 EUI 节点渲染文件                  |
| Server           | 优先复用     | 保留 HTTP 服务架构                   |
| Workspace        | 重写业务逻辑   | 从 FairyGUI Package 改为 Egret 工程 |
| MCP              | 优先复用基础设施 | 修改工具参数和业务实现                    |
| Selection        | 复用机制     | 将 fgui 标识替换为 egret 标识          |
| Tests            | 复用测试框架   | 替换 FairyGUI Fixtures           |
| Browser Selftest | 复用       | 保留浏览器验证能力                      |
| Docs             | 改写       | 清除 FairyGUI 专属文档               |


### 2.2 不做过度抽象

本项目独立维护：

- ExmlNode
- ExmlDocument
- ExmlParser
- ExmlSceneBuilder
- EgretAssetResolver
- EgretWorkspace

不引入通用 UI Intermediate Model，也不为了未来多引擎支持修改 FairyGUI 项目。

### 2.3 保留原始语义

每个 Scene Node 应同时保存：

1. 统一的基础属性。
2. EXML 原始标签。
3. EXML 原始属性。
4. EXML 源文件和节点定位信息。
5. 当前不支持的特性。

例如：

```
{
  "type": "image",
  "id": "node_001",
  "name": "icon",
  "bounds": {
    "x": 20,
    "y": 30,
    "width": 64,
    "height": 64
  },
  "native": {
    "tag": "e:Image",
    "class": "eui.Image",
    "attributes": {
      "source": "icon_png",
      "scale9Grid": "10,10,20,20"
    }
  },
  "unsupported": []
}
```

以上是目标数据结构示例，实际属性以真实 Egret EXML 样本为准。

## 五、第二阶段：EXML Parser

### P0-B：建立 EXML 解析链路

目标：实现 XML → ExmlDocument。

#### B1：EXML 格式调研

首先选取真实 Egret 工程，不能只使用人工编写的 XML。

重点检查：

- XML Namespace。
- EXML 根节点。
- EUI 组件标签。
- 属性命名。
- 子节点结构。
- 图片资源引用。
- 自定义组件标签。
- 节点坐标和布局属性。

需要区分：

- XML 标签名。
- XML Namespace。
- 实际 EUI Class。
- 节点名称。
- 原始属性。

不能简单通过字符串匹配判断组件类型。

#### B2：建立 ExmlDocument 类型

建议定义：

```
interface ExmlDocument {
  file: string;
  root: ExmlNode;
  namespace: Record<string, string>;
  diagnostics: ExmlDiagnostic[];
}

interface ExmlNode {
  id?: string;
  name?: string;

  tag: string;
  className: string;

  attributes: Record<string, unknown>;

  children: ExmlNode[];

  sourceLocation?: {
    line?: number;
    column?: number;
  };
}

interface ExmlDiagnostic {
  level: "warning" | "error";
  code: string;
  message: string;
  nodeId?: string;
}
```

这里的 ExmlDocument 是 XML 语法解析结果，不直接承担 HTML 渲染职责。

#### B3：XML 解析

使用现有的 `fast-xml-parser`。

要求：

1. 保留 XML 节点顺序。
2. 保留 Namespace 信息。
3. 保留原始属性。
4. 支持嵌套节点。
5. 处理 XML 特殊字符。
6. 正确识别根节点。
7. 解析失败时返回明确错误。

特别注意：不能依赖普通 JSON 对象的属性顺序来决定 UI 节点的 z-order。

#### B4：基础组件识别

P0 首批支持：


| Egret EUI 类型                  | 目标映射   |
| ----------------------------- | ------ |
| [eui.Group](http://eui.Group) | group  |
| eui.Image                     | image  |
| eui.Label                     | label  |
| eui.Button                    | button |
| eui.Rect                      | rect   |


对其他节点：

- 保留原始 XML 信息。
- 保留 children。
- 记录 unsupported。
- 不允许静默丢失节点。

**验收标准：**

- 能解析真实 EXML。
- 节点数量与 XML 一致。
- 层级顺序正确。
- 原始属性无丢失。
- Namespace 解析正确。
- 未知节点可以明确诊断。

## 六、第三阶段：Scene Builder

### P0-C：EXML AST → Scene Tree

目标：建立独立于 XML 语法的渲染数据结构。

#### C1：节点基础结构

```
interface SceneNode {
  type: string;

  id?: string;
  name?: string;

  bounds?: {
    x: number;
    y: number;
    width: number;
    height: number;
  };

  attrs: Record<string, unknown>;

  native: {
    tag: string;
    className: string;
    attributes: Record<string, unknown>;
  };

  children: SceneNode[];

  instancePath: string;
  stableKey: string;

  unsupported: string[];
}
```

#### C2：基础属性转换

第一阶段只处理：

- x
- y
- width
- height
- alpha
- rotation
- scaleX
- scaleY
- visible

文本节点额外处理：

- text
- fontSize
- textColor
- bold
- italic
- textAlign
- verticalAlign

图片节点额外处理：

- source
- fillMode

以上属性应按实际样本验证后再纳入支持列表。

#### C3：坐标规则

P0 以绝对定位为主要渲染方案。

优先处理：

```
x
y
width
height
```

对于：

- left
- right
- top
- bottom
- horizontalCenter
- verticalCenter
- percentWidth
- percentHeight

先记录和识别，不立即实现完整布局计算。

如果样本中这些属性是实现基本页面显示不可缺少的，可以增加最小静态计算支持，但不引入完整 EUI Layout 系统。

#### C4：节点标识

沿用 FairyGUI 项目已经验证的双标识设计：

- instancePath：可读节点路径。
- stableKey：唯一实例键。

同时保留原始 id 和 name。

**验收标准：**

- XML 与 Scene Tree 节点数量一致。
- 父子关系正确。
- 节点顺序正确。
- 属性转换正确。
- stableKey 不重复。
- 未支持特性完整上报。

## 七、第四阶段：资源解析

### P0-D：EgretAssetResolver

目标：解决 EXML 图片资源引用问题。

这是必须独立实现的模块，不能复用 FairyGUI 的 package.xml 资源索引。

#### D1：工程资源探测

先检查真实 Egret 工程：

- EXML 文件所在目录。
- resource 目录。
- assets 目录。
- resource/default.res.json。
- 图片文件实际位置。
- EXML source 的实际引用形式。

先建立资源引用样本清单，再确定解析规则。

#### D2：基础资源解析

建立：

```
interface EgretAssetResolver {
  resolve(
    source: string,
    exmlFile: string
  ): ResolvedAsset | null;
}
```

要求：

1. 支持 P0 样本实际使用的资源引用形式。
2. 能定位真实图片文件。
3. 支持相对路径。
4. 处理资源不存在的情况。
5. 防止路径穿越。
6. 返回可供 HTML Renderer 使用的资源地址。

资源 ID 到真实路径的映射规则必须根据真实 Egret 工程确定，不预先假设所有 source 都是文件路径。

#### D3：资源诊断

资源无法解析时：

- 输出原始 source。
- 输出所属 EXML 文件。
- 输出解析失败原因。
- 不允许直接替换为随机图片或空白内容而不提示。

**验收标准：**

真实 EXML 引用的图片能够在浏览器中显示。

## 八、第五阶段：HTML Renderer

### P0-E：Scene Tree → HTML

目标：尽可能复用 FairyGUI 渲染器的组织方式，建立 Egret 专属节点渲染。

#### E1：渲染器主入口

保留：

```
src/renderer/html-renderer.ts
```

但重写其输入类型和节点分发逻辑，使其只依赖 Egret Scene Tree。

#### E2：节点渲染

一类型一文件：


| 文件             | 职责     |
| -------------- | ------ |
| group-node.ts  | 容器和子节点 |
| image-node.ts  | 图片     |
| label-node.ts  | 文本     |
| button-node.ts | 按钮基础视觉 |
| rect-node.ts   | 矩形     |


不要把所有节点渲染逻辑放到 html-renderer.ts。

公共样式计算、HTML 转义、属性处理可以放到 utils.ts。

#### E3：基础视觉还原

统一使用：

```
position: absolute;
```

第一阶段处理：

- 坐标。
- 尺寸。
- 背景。
- 透明度。
- 旋转。
- 缩放。
- 图片显示。
- 文本显示。
- 子节点层级。

暂不模拟按钮交互、动画、布局容器的完整运行时行为。

#### E4：DOM 语义标识

每个可见节点添加：

```
data-egret-id=""
data-egret-name=""
data-egret-type=""
data-egret-path=""
data-egret-key=""
```

用于：

- 浏览器节点定位。
- 点击选择。
- 高亮。
- 后续 MCP 查询。
- AI 组件检索。

#### E5：Unsupported 展示

HTML 预览页面需要保留未支持特性诊断信息。

不能让用户误认为渲染结果已经完整还原了 EUI。

**验收标准：**

- 图片正确显示。
- 文本正确显示。
- 节点位置和尺寸正确。
- 层级正确。
- 未支持特性有明确记录。

## 九、第六阶段：工作区与 MCP 迁移

### P0-F：保留已有基础设施

这一阶段以最小改造为原则，不重新开发工作台。

#### F1：Workspace

原项目的：

- listPackages
- listComponents
- component search

都依赖 FairyGUI Package，需要替换。

Egret 第一阶段改为：

- 获取工程信息。
- 枚举 EXML 文件。
- 根据路径读取 EXML。
- 获取 Scene JSON。
- 解析资源路径。

建议接口：

```
interface EgretWorkspace {
  getProjectInfo(): ProjectInfo;

  listExmlFiles(): ExmlFileInfo[];

  getScene(file: string): SceneDocument;

  getAsset(path: string): AssetInfo;
}
```

不再保留 Package、Resource ID 等 FairyGUI 专属概念。

#### F2：HTTP Server

尽量复用原项目的：

- 原生 Node HTTP Server。
- 路径安全校验。
- 每次请求重新解析。
- 静态资源服务。
- 内嵌预览页面。

建议路由：


| 路由                   | 作用         |
| -------------------- | ---------- |
| GET /api/project     | 工程信息       |
| GET /api/exml        | EXML 文件清单  |
| GET /api/scene?file= | Scene JSON |
| GET /api/assets/\*   | 图片资源       |
| GET /view?file=      | HTML 预览    |
| GET /                | 工作区        |


保留路径穿越防护和本地工程目录隔离。

#### F3：Selection

复用原有选择机制：

- 点击节点。
- 获取节点 id。
- 获取节点 name。
- 获取节点类型。
- 获取源文件。
- 返回层级路径。
- 高亮当前节点。
