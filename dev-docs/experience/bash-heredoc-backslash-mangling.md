# Bash heredoc 反斜杠吞噬问题

- 日期：2026-11-05
- 场景：在 Windows（WSL/Git Bash）环境下用 `cat > file << 'EOF'` 写含正则/模板字面量的 TS 脚本

## 现象

heredoc（即使带引号定界符 `<< 'EOF'`）写入的 `\\s`、`\\S`、`\\/` 等双反斜杠序列
到文件里变成单反斜杠 `\s`、`\S`、`\/`。

P1-C 冒烟脚本中模板字面量 `new RegExp(\`...[\\s\\S]*?<\\/div>\`)` 被写成
`[\s\S]*?<\/div>`，JS 模板字面量里 `\s` 退化为 `s`，正则变成 `[sS]*?`，
匹配静默失败（返回 null）——产出的结论是"真实工程位图数字 0 位片"，
而 debug 脚本证明产品代码完全正常。

## 注意事项

1. 用 write 工具或 edit 工具写含反斜杠的脚本，不用 heredoc。
2. heredoc 写完的文件必须先 `grep`/`sed -n` 回读关键行确认转义正确再执行。
3. 冒烟脚本报"功能坏了"而单元断言全绿时，先怀疑测试脚本本身：
   用最小 debug 脚本（indexOf + slice 而非正则）交叉验证。
4. 本环境 heredoc 既有挂起史（前次会话），又有转义吞噬，一律改用 write 工具。
