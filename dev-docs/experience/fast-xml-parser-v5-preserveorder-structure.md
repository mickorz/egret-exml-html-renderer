# fast-xml-parser v5 preserveOrder 输出结构与预期不符

## 问题现象

按 fast-xml-parser 常见文档示例假设 preserveOrder 模式输出为 `[{ "?:": "e:Skin", ":@": {...}, "e:Group": [...] }]`
（每个元素带 `?:` 标签名键），首次运行解析器时所有根节点判定失败（实际 0 个顶层元素）。

## 排查过程

直接用 node 打印 `parser.parse()` 的原始输出，发现 v5 的真实结构与假设不同。

## 根因

fast-xml-parser v5 的 preserveOrder 模式下，**每个元素对象的唯一非 `:@` 键就是标签名本身**：

```json
[
  {
    "e:Skin": [ { "e:Group": [] } ],
    ":@": { "class": "T", "xmlns:e": "http://ns.egret.com/eui" }
  }
]
```

- 没有 `?:` 键；标签名 = 对象里除 `:@` 外的那个键；
- 纯文本节点是 `{ "#text": "..." }`；
- XML 声明 `<?xml ...?>` 会作为 `?xml` 键出现在顶层数组（**会被误判成根元素**）；
- 自闭合标签 `<e:Group/>` 的子数组是 `[]`。

## 解决方案

1. `tagOf(item)`：遍历对象键，跳过 `:@`，返回第一个键；`#text` / `?` 开头 / `!` 开头视为非元素项返回 null。
2. 顶层根元素判定前先过滤非元素项（XML 声明、注释）。

## 预防/注意事项

- 升级解析库版本时先打印真实输出再写转换层，不要凭旧版文档/教程假设结构。
- 顶层元素计数必须排除 `?xml` 声明，否则带声明头的 EXML 全部误判为"多根节点"。
